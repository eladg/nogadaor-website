# האתר של נוגה דיין-אור – הגדרות בסיס

הסקיל הזה נשמר בתוך הריפוזיטורי (`.claude/skills/noga-website/SKILL.md`) ומנוהל ב-Git יחד עם האתר, ולא בתיקייה האישית. הוא נטען כשהסשן נפתח בתיקיית `website`. כל מידע חדש על הפרויקט נשמר כאן ולא בתיקייה האישית.

טען את הסקיל הזה לפני עבודה על האתר. הוא מתאר מה כבר הוחלט ונבנה (נכון ל-2026-11-04), איך עובדים עם נוגה, ומה עדיין פתוח.

## 1. כללי עבודה עם נוגה (חובה)
- נוגה אינה מפתחת. מסבירים בעברית פשוטה, בלי ז'רגון.
- **לא מפרסמים שום דבר באינטרנט (אירוח, דומיין, שיתוף האתר) בלי שנוגה ביקשה במפורש**, ובכל פעם מחדש.
- **push ל-GitHub (גיבוי בלבד, המאגר פרטי): נוגה אישרה ב-2026-11-04 לדחוף בעצמי בערך כל 3-4 החלפות הודעות, כדי שהיא לא תצטרך לזכור.** לפני דחיפה לוודא ש-`npm run build` עובר ושאין בהוספה את תיקיית "חומרים גרפיים לאתר" או קבצים רגישים. דוחפים רק ל-`origin main`, בלי force. אחרי כל דחיפה מוסרים לה שורה אחת שהתבצעה. אם ה-push נכשל על הרשאות, מבקשים ממנה להתחבר בטרמינל. ה-push האחרון: `6ee3f3d` (2026-11-05). תיקיית החומרים הגרפיים אינה מגובה, ונוגה אמרה שאין צורך.
- אחרי כל שלב: להריץ `npm run build`, לבדוק בשרת הפיתוח, לבצע commit מקומי עם הודעה ברורה בעברית, ולסכם בקצרה מה נעשה ומה נשאר פתוח.
- סעיפים המסומנים ❓ ב-`REQUIREMENTS.md` הם החלטות שעוד לא התקבלו. לא ממציאים להם תשובות. שואלים שאלה אחת או שתיים בכל פעם. אפשר להתקדם בינתיים בכל מה שלא תלוי בהם.
- **לא ממציאים תוכן.** תוכן שחסר (טקסטים, תמונות, סרטונים) מקבל placeholder ברור בעברית והערת `TODO` בקוד. אין לכתוב תוכן שיווקי על הניסיון, ההשכלה, הלקוחות או התוצאות של נוגה.

## 2. מיקומים וכלים
- ריפוזיטורי: `C:\Users\נוגה\Documents\GitHub\website` (ענף `main`, מרוחק: `https://github.com/nogadaor/website.git`).
- Astro 7.4.5, Node.js 26.13.0 LTS, npm 11. Node מותקן ב-`C:\Program Files\nodejs`. ב-PowerShell של הסשן ייתכן ש-PATH לא כולל אותו, ואז מריצים קודם `$env:Path += ";C:\Program Files\nodejs"`.
- שרת פיתוח: `npx astro dev --background` (כתובת http://localhost:4321). מצב: `npx astro dev status`. עצירה: `npx astro dev stop`.
- בנייה: `npm run build`.
- Git ב-PowerShell: הודעות commit עם גרשיים או כמה שורות שוברות את המעבר של הארגומנט. הדרך היציבה: לכתוב את ההודעה לקובץ ולהריץ `git commit -F <קובץ>`. אזהרות "LF will be replaced by CRLF" אינן שגיאה. פלט `NativeCommandError` אדום מ-`git push` הוא רק אופן ההצגה, ואין להסיק ממנו כישלון: בודקים עם `git status -sb` ו-`git log origin/main`.
- Git לא מחובר ל-GitHub מתוך הסביבה של Claude באופן עצמאי. ה-push הראשון הצליח רק אחרי שנוגה התחברה בעצמה. אם ה-push נכשל על הרשאות, מבקשים ממנה להתחבר בטרמינל שלה. אף פעם לא מבקשים או מזינים סיסמה או טוקן.
